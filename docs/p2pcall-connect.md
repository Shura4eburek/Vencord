# P2PCall — как подключиться

Прямые звонки в ЛС Discord (голос, камера, экран) без серверов Discord. Работает, только если плагин
стоит у **обоих** собеседников.

Ветка: `feat/p2p-call` в `<корень Vencord>`. Код плагина: `src/userplugins/p2pCall/`.

## 1. Установка (у каждого собеседника)

Нужны Node.js 18+, pnpm и git.

```bash
git clone <репозиторий форка Vencord> Vencord
cd Vencord
git checkout feat/p2p-call
pnpm install
pnpm build
pnpm inject          # выбрать свою установку Discord (Stable / PTB)
```

У Mamoru всё уже собрано и заинжекчено в Discord Stable — после перезагрузки ничего делать не нужно.

Передать сборку другу без git: заархивировать папку Vencord целиком (с `dist/` и `node_modules/`),
у друга распаковать и выполнить `pnpm inject` из этой папки.

## 2. Включение

1. **Полностью** перезапустить Discord: трей → «Выйти», затем открыть снова. Ctrl+R мало — CSP для
   релеев задаётся при старте main-процесса.
2. Настройки → Vencord → Плагины → **P2PCall** → включить.
3. Ещё раз Ctrl+R (патчи интерфейса применяются при загрузке клиента).

Настройки плагина по умолчанию подходят. Три выпадающих списка без подписей — это, сверху вниз,
микрофон, устройство вывода и камера: если в Discord выбраны не системные устройства, выбрать те же.

## 3. Как звонить

- Открыть ЛС с собеседником. В **шапке** справа, рядом с обычными кнопками звонка, — иконка
  «трубка + цепь».
  - клик — голосовой звонок;
  - Shift+клик — сразу с камерой.
- У собеседника по центру появится окно «Входящий P2P-звонок»: «Принять», «Принять с видео»,
  «Отклонить».
- После ответа над сообщениями — область звонка: плитки участников (зелёная обводка у говорящего),
  кнопки микрофона, звука, камеры, экрана и сброса. Высоту можно тянуть за нижний край, двойной
  клик по видео — на весь экран.
- В углу области — пинг, потери и тип канала. **«напрямую»** — звонок идёт P2P. «через
  ретранслятор» — не P2P.
- Если уйти из ЛС, слева внизу над аккаунтом останется плашка «P2P подключено» с кнопками.

## 4. Если что-то не так

| Симптом | Что делать |
|---|---|
| Интерфейс Discord глючит или пропал кусок после запуска | Настройки → Vencord → Плагины → выключить **P2PCall**, перезапустить Discord. Всё вернётся как было |
| Иконка в шапке серая, подсказка «нет связи с сигналингом» | Полностью перезапустить Discord (трей → Выйти). Если не помогло — консоль (Ctrl+Shift+I), фильтр `wss://` или `P2PCall`, прислать ошибки |
| Иконки в шапке нет | Консоль, фильтр `P2PCall`: строка `Patch ... had no effect` значит, Discord обновился и патч надо поправить (`patches.ts`, фрагменты в `patches.test.ts`) |
| «Прямое соединение не установилось» | NAT не пробился. См. раздел 5 |
| Не слышно собеседника | Проверить устройство вывода в настройках плагина и не включён ли deafen (наушники перечёркнуты) |

Логи Discord с ошибками рендерера: `%APPDATA%\discord\logs\renderer_js.log`.

## 5. Сеть

- **Mamoru:** провайдер-А, двойной NAT (роутер + CGNAT провайдера), публичный `203.0.113.10`. NAT
  не симметричный (один внешний порт на все адресаты), но порт не сохраняется.
- **Друг:** провайдер-Б, NAT не симметричный. Между разными провайдерами обычная пробивка WebRTC
  через STUN должна работать — **ещё не проверено вживую**.
- **Собеседник у того же провайдера (провайдер-А):** обычный ICE не соединяется — пакеты Mamoru
  приходят к нему с внутреннего адреса провайдера `100.64.0.10`, а ответы на этот адрес роутер
  Mamoru режет; роутер друга режет входящие без проброса. Подробности:
  `отчёт о живом тесте NAT (хранится локально, вне репозитория)`.
  Для этого случая есть **UDP-туннель** (`tunnel.ts`, `upnp.ts`, спека `specs/001-udp-tunnel-upnp`):
  на время звонка плагин сам открывает UDP-порт 40000–40999 на роутере через UPnP, шлёт на оба адреса
  собеседника и даёт WebRTC дополнительный кандидат на свой LAN-адрес. В чипе путь —
  «напрямую (туннель)». Настраивать ничего не нужно; если звонок не соединился, а на роутере
  выключен UPnP, уведомление подскажет включить его. Проверить, что роутер отвечает: в логе
  `[P2PCall] tunnel` поле `upnp` — `ok` (порт открыт), `no-igd` (UPnP выключен или не поддерживается).

Проверить свой NAT: `node natcheck.mjs` (скрипт в той же папке, что и отчёт). Одинаковый `ip:port`
от всех серверов — пробиваемый NAT; разные — симметричный, P2P почти наверняка не выйдет.

## 6. Обновления

Автообновление (и кнопка «Проверить обновление» в настройках плагина) качает из релиза только
изменившиеся файлы и пишет, что нужно сделать:

- **ничего** — поменялась только сетевая часть (туннель, UPnP); она подхватится со следующего звонка;
- **перезагрузить окно** — поменялись интерфейс или логика звонка; кнопка в уведомлении, пара секунд;
- **перезапустить Discord** — поменялась часть, которая грузится при старте Discord (обвязка плагина,
  CSP релеев, само автообновление).

Во время P2P-звонка ничего не перезагружается: уведомление придёт после сброса. Первое обновление со
старой версии (до 2026.10.18-3) всегда просит перезапуск, после него сетевая часть докачивается сама.
Рабочая сборка из репозитория не обновляется; после `pnpm build` сетевая часть подхватывается со
следующего звонка, остальное — Ctrl+R или перезапуском.

Релиз: `npx tsx src/userplugins/p2pCall/tools/release.ts "что изменилось"` — сам собирает
детерминированную сборку и публикует оба манифеста (`manifest.json` для старых копий и `manifest-v2.json`).

## 7. Контакты и ключи

С версии после 2026.10.18-3 у каждой установки свой ключ. Как только у вас с собеседником есть общий ЛС и
оба онлайн (открыли ЛС, звоните или просто запустили Discord), плагины сами обмениваются ключами — без
сообщений в чате и без серверов. Контакты видны в настройках плагина → «Контакты и ключи P2P».

- **Код проверки** — 8 цифр, одинаковые у обоих. Сверьте голосом в звонке и отметьте «код сверен»: тогда
  ключи защищены даже от подмены самим Discord.
- **«Новый ключ P2P»** — у собеседника новое устройство или переустановка (или кто-то подменяет ключ).
  Звонки с новым ключом не принимаются: сверьте код этого устройства и нажмите «Подтвердить» (или
  «Отклонить»).
- Звонок без ключа сначала обменивается ключами (до 8 с). Не вышло — «Нет ключа P2P с собеседником»: у него
  старая версия P2PCall (обновится сама, автообновлением) или он не в сети. Старой схемы без ключей больше нет.
- Ключ лежит в `%APPDATA%\discord\p2pcall-identity.bin` (зашифрован Windows), контакты — рядом.

## 8. Что ещё не сделано

- Ручная проверка нового интерфейса в двух клиентах.
- Ключ пары: сейчас ключ сигналинга выводится из ID канала и подбирается перебором — посторонний на
  публичных релеях Nostr может прочитать IP-адреса и вклиниться в звонок. План: общая фраза в
  настройках у обоих.
- Групповые звонки.
