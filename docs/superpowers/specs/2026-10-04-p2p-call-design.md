# P2PCall — прямые звонки в ЛС в обход серверов Discord

Дата: 2026-10-04
Статус: дизайн согласован, ждёт ревью спеки

## Цель

Звонить другу в ЛС напрямую (P2P), а не через медиасерверы Discord (Варшава/Амстердам, 20–40 мс).
Оба собеседника в одном городе, прямой канал между ними — порядка 1 мс. Плагин работает, только если он
установлен у обоих.

**Критерии успеха** (боевой звонок Mamoru ↔ Друг):

- тип ICE-пары `host` или `srflx` (не `relay`);
- RTT < 10 мс;
- потери ≈ 0 %;
- стрим экрана 1080p60 без фризов.

**Что известно о сети:** у Mamoru CGNAT, у Друг — свой NAT. Оба NAT не симметричные: STUN-ответы
от разных серверов с одного сокета дают одинаковый внешний порт, поэтому прямой канал пробивается
через STUN.

## Не делаем (YAGNI)

- Свои серверы, Cloudflare Workers, TURN, cloudflared, Tailscale.
- Групповые звонки — только 1:1.
- Перехват или замену нативного голосового движка Discord (`discord_voice`): P2P-звонок — отдельный
  звонок внутри клиента.
- Krisp: используется только шумодав Chromium.

## Архитектура

Пользовательский плагин `src/userplugins/p2pCall/`, устроен по образцу `rtcGuard`.

| Файл | Назначение |
|---|---|
| `index.ts` | `definePlugin`, настройки, кнопка «P2P-звонок» в шапке ЛС, тост входящего звонка, жизненный цикл |
| `signaling.ts` | Сигналинг поверх Nostr: подписка на линию и комнату звонка, отправка и приём зашифрованных сообщений |
| `crypto.ts` | Вывод тем и ключа, шифрование и расшифровка (чистые функции) |
| `state.ts` | Автомат состояний звонка (чистая логика, без WebRTC) |
| `session.ts` | `RTCPeerConnection`, perfect negotiation, треки, `getStats()` |
| `sdp.ts` | Правка SDP: параметры Opus и `ptime` (чистые функции) |
| `media.ts` | Захват микрофона, камеры и экрана, вывод звука на выбранное устройство |
| `native.ts` | `desktopCapturer.getSources()` в main-процессе — список экранов и окон с превью |

Новые зависимости в `package.json`: `nostr-tools`, `@noble/ciphers`, `@noble/hashes`.

## Сигналинг

**Транспорт.** Временные (ephemeral) события Nostr `kind: 25050`: релеи их пересылают, но не хранят.
Релеи по умолчанию: `wss://relay.damus.io`, `wss://nos.lol`, `wss://nostr.mom`, список меняется в
настройках. Каждое сообщение уходит во все релеи, дубли на приёме отбрасываются по `msgId`.
Ключевая пара Nostr генерируется заново на каждый запуск и ни к какому аккаунту не привязана.

**Темы** (тег `t`):

- линия пользователя: `sha256("p2pcall-v1:line:" + userId)` — на неё подписан каждый клиент с
  момента старта плагина, сюда приходит `ring`;
- комната звонка: `sha256("p2pcall-v1:call:" + callId)` — все остальные сообщения звонка, где
  `callId` — 16 случайных байт.

**Подсказка канала.** `ring` приходит на линию до того, как вызываемый знает, из какого ЛС звонят, а
без этого ему не вывести ключ. Поэтому у `ring` есть открытый тег `c = sha256("p2pcall-v1:pair:" + channelId)`.
Вызываемый сверяет его с хешами своих ЛС 1:1 из `ChannelStore` и по совпадению берёт `channelId`.
Хеши кешируются и пересчитываются при появлении нового ЛС.

**Шифрование.** XChaCha20-Poly1305 (`@noble/ciphers`).
Ключ: `HKDF-SHA256(ikm = channelId + ":" + min(uidA, uidB) + ":" + max(uidA, uidB), info = "p2pcall-v1")`.
Это отступление от NIP-44, оговорённого в части 2 дизайна: NIP-44 требует заранее знать публичный
ключ собеседника, а сессионные ключи случайные, поэтому нужен симметричный ключ.

**Сообщения** (JSON внутри шифртекста, у каждого есть `msgId`, `callId`, `from`, `ts`):

| Тип | Поля | Направление |
|---|---|---|
| `ring` | `channelId`, `video: bool` | вызывающий → линия вызываемого |
| `accept` / `decline` | — | вызываемый → комната |
| `offer` / `answer` | `sdp` | обе стороны → комната |
| `ice` | `candidate` | обе стороны → комната |
| `bye` | `reason` | обе стороны → комната |

Сообщения старше 30 с (по `ts`) и с `from`, не совпадающим с собеседником по ЛС, отбрасываются.

**Модель угроз.** Ключ выводится из ID, которые не секретны. Злоумышленник, знающий ID канала и ID
обоих пользователей и поставивший такой же плагин, теоретически может позвонить или вклиниться в
сигналинг. Медиа всё равно шифруется DTLS-SRTP. Для звонков между двумя друзьями риск принят.

## Ход звонка

Состояния: `idle → outgoing | incoming → connecting → connected → ended → idle`.

| Переход | Условие |
|---|---|
| `idle → outgoing` | нажата кнопка, отправлен `ring` |
| `idle → incoming` | пришёл `ring` от собеседника по ЛС, показан тост со звуком |
| `outgoing → connecting` | пришёл `accept` |
| `incoming → connecting` | нажато «Принять», отправлен `accept` |
| `connecting → connected` | ICE `connected` |
| `outgoing → ended` | `decline` или 30 с без ответа |
| `connecting → ended` | ICE не соединился за 10 с, тост с откатом: «Не удалось, звонить через Discord?» |
| `connected → ended` | `bye`, сброс или ICE `failed` |
| любое → `ended` | вызов во время другого звонка: `decline` с `reason: "busy"` |

**Perfect negotiation.** Вежливая сторона — та, у кого user ID меньше (сравнение через `BigInt`).
Поэтому экран и камеру можно добавлять и убирать посреди звонка без конфликтов.

**ICE:** `iceServers`: `stun:stun.l.google.com:19302`, `stun:stun.cloudflare.com:3478`.
Кандидаты передаются по одному (trickle ICE). При `disconnected` — один `restartIce()`, при `failed` —
завершение звонка и тост с откатом.

## Медиа

**Голос:**

- `getUserMedia({ audio: { echoCancellation, noiseSuppression, autoGainControl, deviceId } })`;
- Opus в `a=fmtp`: `useinbandfec=1;maxaveragebitrate=128000;minptime=10`, плюс `a=ptime:10`;
- на приёме `receiver.jitterBufferTarget = 0`;
- вывод через `<audio>` с `setSinkId(outputDeviceId)`.

**Экран:**

- источник выбирается в `SourcePicker` по списку из `native.ts`, захват через
  `getUserMedia({ video: { mandatory: { chromeMediaSource: "desktop", chromeMediaSourceId } } })`;
- до 1920×1080 при 60 fps, `maxBitrate` 8 Мбит/с через `sender.setParameters`;
- `contentHint`: `motion` (плавность) или `detail` (чёткость), переключатель в панели;
- `degradationPreference`: `maintain-framerate` для `motion`, `maintain-resolution` для `detail`;
- кодек: приоритет VP9, затем H.264 через `setCodecPreferences`;
- звук системы не передаётся (первая версия).

**Камера:** 1280×720 при 30 fps.

**Устройства:** микрофон, вывод и камера выбираются в настройках плагина по списку
`enumerateDevices()`. Устройства из настроек Discord не используются: нативный движок нумерует их
по-своему.

## Интерфейс

- **Кнопка** «P2P-звонок» в шапке ЛС, только для личных переписок 1:1.
- **Входящий звонок:** тост с аватаром, «Принять» и «Отклонить», звук вызова.
- **`CallPanel`:**
  - плавающая, перетаскивается;
  - видео собеседника (экран или камера) и своё превью;
  - кнопки 🎤 / 📷 / 🖥️ / 📞 и переключатель «плавность/чёткость»;
  - полоска статистики раз в секунду: RTT (`candidate-pair.currentRoundTripTime`), потери %,
    битрейт, тип канала (`host` / `srflx` / `relay`);
  - двойной клик по видео — во весь экран, есть компактный режим (только кнопки и пинг).
- Если пользователь одновременно в голосовом канале Discord, при старте P2P-звонка показывается
  тост-предупреждение. Автоматически ничего не отключается.

## Обработка ошибок

| Ситуация | Поведение |
|---|---|
| Релей отвалился | переподключение с паузой 1 → 2 → 4 … 30 с, остальные релеи продолжают работать |
| Все релеи недоступны | кнопка звонка неактивна, подсказка «Нет связи с сигналингом» |
| Нет доступа к микрофону или камере | тост с причиной, звонок без этого трека |
| Источник экрана закрыт | трек убирается, перезапуск через perfect negotiation |
| Собеседник не отвечает или ICE не прошёл | тост с откатом на обычный звонок Discord |
| Сообщение не расшифровалось или устарело | молча отбрасывается |

## Проверка

**Модульные тесты** — `node:test`, запуск `npx tsx --test src/userplugins/p2pCall/*.test.ts`:

- `state.test.ts` — все переходы и таймауты, busy;
- `crypto.test.ts` — одинаковый ключ у обеих сторон независимо от порядка ID, шифрование туда-обратно,
  отказ при чужом ключе;
- `sdp.test.ts` — вставка параметров Opus и `ptime`, SDP без Opus не ломается;
- выбор вежливой стороны — ID длиннее 2^53 сравниваются корректно.

**Сборка:** `pnpm testTsc`, `pnpm lint`, `pnpm build`.

**Ручная проверка на одном ПК:** Discord + Discord PTB, оба с Vencord, звонок между двумя
аккаунтами. Ожидается тип канала `host`, работают голос, камера, экран, сброс, отклонение, таймаут.

**Боевая проверка с Друг:** критерии успеха из раздела «Цель».

## Риски

- `desktopCapturer` в main-процессе Discord может быть недоступен или ограничен. Запасной путь —
  `getDisplayMedia` через обработчик, который Discord ставит сам.
- Публичные релеи Nostr могут ограничивать частоту событий. ICE-кандидатов немного (trickle,
  2 стороны), но при необходимости их можно собирать в пачки по 100 мс.
- Обновление Discord может сломать патч для кнопки в шапке ЛС, как и у любого плагина Vencord.
