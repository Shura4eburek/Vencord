# P2PCall — демка v2

Дата: 2026-10-06
Статус: дизайн согласован, ждёт ревью спеки
Часть 1 из 4 доработок после первого живого теста (2 — звук и устройства, 3 — просмотр, 4 — звук демки).

## Цель

Демка без просадок на сложной картинке и с качеством на выбор, как в Discord Go Live, но без его
лимитов: до 1440p (исходное разрешение монитора) и до 120–144 FPS, с аппаратным кодеком и видимой
причиной, если качество всё-таки падает.

**Критерии успеха:**
- демка 1440p120 у Mamoru (видеокарта с аппаратным AV1, монитор 1440p с высокой частотой) идёт аппаратным кодером;
- на сцене с большим количеством эффектов битрейт держится у выбранного потолка, если канал позволяет;
- при просадке в чипе и в логе видна причина: `cpu`, `bandwidth` или `none`;
- качество меняется на ходу без разрыва звонка.

## Не делаем (YAGNI)

- Звук демки (часть 4), настройки вебки (часть 2), полноэкранный просмотр (часть 3).
- Смену кодека посреди демки: кодек выбирается при старте демки.
- Апскейл выше исходного разрешения источника.

## Выбор качества

### В окне выбора экрана (`ui/SourcePicker.tsx`)

Под списком источников — панель:

| Параметр | Значения | По умолчанию |
|---|---|---|
| Разрешение (предел по высоте) | 720p, 1080p, 1440p, исходное | исходное |
| FPS | 30, 60, 120, 144 | 60 |
| Потолок битрейта | 10, 20, 40, 80 Мбит/с | 20 |
| При нехватке канала | держать FPS / держать чёткость | держать FPS |

- Частота монитора измеряется в окне выбора: `requestAnimationFrame` в течение 500 мс, средний
  интервал → Гц. Значения FPS выше измеренной частоты + 5 % — серые.
- Последний выбор сохраняется в настройках плагина (скрытые поля) и подставляется в следующий раз.

### На ходу (`ui/StreamQualityMenu.tsx`)

Стрелочка рядом с кнопкой демки в области звонка (и в плашке над аккаунтом) открывает меню с теми же
четырьмя параметрами. Выбор применяется сразу.

## Захват и кодер

- Разрешение: `maxHeight` = выбранное значение (для «исходное» — без ограничения), `maxWidth`
  считается по пропорциям источника; Chromium масштабирует с сохранением пропорций.
- FPS: `maxFrameRate` захвата и `encodings[0].maxFramerate` кодера = выбранное значение.
- Потолок: `encodings[0].maxBitrate`.
- «При нехватке»: `degradationPreference` = `maintain-framerate` / `maintain-resolution`;
  `contentHint` = `motion` / `detail`.
- Стартовый битрейт: в SDP для видео-кодеков демки `x-google-start-bitrate` = min(потолок / 2,
  10 000) кбит/с, чтобы не было нескольких секунд «мыла» на старте. Реализуется в `sdp.ts`.

### Смена на ходу

1. Разрешение / FPS → `track.applyConstraints(...)`.
2. Если отклонено или фактические `getSettings()` не изменились → новый захват того же источника,
   `sender.replaceTrack(newTrack)` (без пересогласования), старый трек останавливается.
3. Потолок / «при нехватке» → `sender.setParameters(...)`.
4. Если не удались и 1, и 2 → тост «Не удалось сменить качество демки», режим остаётся прежним.

## Кодек

### Возможности

При открытии data channel `ctl` каждая сторона отправляет:
```json
{ "type": "caps", "encodeHw": ["video/AV1", "video/H264"], "decodeHw": ["video/AV1", "video/H264", "video/VP9"] }
```
Списки строятся через `navigator.mediaCapabilities.encodingInfo/decodingInfo`
(`type: "webrtc"`, 1920×1080 @ 60, 20 Мбит/с) — в список попадает кодек с `supported && powerEfficient`.

### Выбор (чистая функция в `codecs.ts`)

Отправитель демки выбирает кодек для своей отправки:

1. Если в настройках плагина задан ручной кодек — он.
2. Иначе первый из `AV1, H264, VP9`, который есть в своём `encodeHw` и в `decodeHw` собеседника.
3. Если такого нет или `caps` собеседника ещё не пришли — `H264`.

Применяется через `transceiver.setCodecPreferences` (выбранный кодек первым, остальные за ним).

## Статистика и лог

`stats.ts` дополнительно собирает из `outbound-rtp` / `inbound-rtp` видео:

- `frameWidth`, `frameHeight`, `framesPerSecond` (отправка и приём);
- `encoderImplementation`, `powerEfficientEncoder` → «аппаратный / программный»;
- `qualityLimitationReason` (`none | cpu | bandwidth | other`);
- кодек (`codecId` → `codec.mimeType`).

**Чип в области звонка при идущей демке:** `1440p · 120 FPS · AV1 (аппаратный) · 38 Мбит/с ·
ограничение: канал`.

**`diagLog.ts`:** пока звонок в фазе `connected`, раз в 5 с — `console.info("[P2PCall] stats", JSON)`
со сводкой (RTT, потери, путь, параметры видео в обе стороны, причина ограничения). Строки попадают в
`%APPDATA%\discord\logs\renderer_js.log`.

## Настройки плагина (новые)

| Ключ | Тип | По умолчанию |
|---|---|---|
| `screenCodec` | выбор: авто / AV1 / H.264 / VP9 | авто |
| `screenHeight`, `screenFps`, `screenMaxMbps`, `screenPrefer` | скрытые, последний выбор | исходное / 60 / 20 / fps |
| `diagLog` | bool «Писать статистику в лог» | true |

Старая настройка `screenMaxBitrateMbps` удаляется (её роль — потолок в окне выбора).

## Ошибки

| Ситуация | Поведение |
|---|---|
| Источник не дал запрошенный режим | Берётся ближайший, в чипе фактические цифры |
| Аппаратный кодер недоступен | Программный, в чипе «(программный)» |
| Смена на ходу не удалась | Тост, прежний режим |
| `mediaCapabilities` недоступен или бросил | Пустые списки → H.264 |

## Разведка в начале реализации

Одноразовая проверка внутри Discord (через консоль или временный лог плагина):

1. Отдаёт ли захват экрана (`chromeMediaSource: desktop`) больше 60 FPS при `maxFrameRate: 120`.
2. Какие кодеки `mediaCapabilities` отмечает `powerEfficient` для кодирования в Discord (Chromium 148).

Если захват ограничен 60 FPS — значения 120/144 убираются из меню, остальное без изменений.

## Проверка

- Модульные тесты:
  - `streamQuality.test.ts` — перевод выбора в ограничения и параметры кодера, серые FPS выше частоты;
  - `codecs.test.ts` — выбор кодека: ручной, AV1 у обоих, AV1 только у одного, нет `caps`, пустые списки;
  - `sdp.test.ts` — `x-google-start-bitrate` добавляется к видеокодекам, не трогает аудио, не дублируется;
  - `stats.test.ts` — новые поля, причина ограничения, аппаратный/программный кодер.
- Существующие тесты зелёные; `pnpm testTsc`, `pnpm lint`, `pnpm build`.
- Ручная проверка с собеседником: 1440p120 AV1, смена качества на ходу, сцена с эффектами, строки
  `[P2PCall] stats` в логе.
