# Quickstart: проверка туннеля

## Автотесты

```bash
npx tsx --test src/userplugins/p2pCall/*.test.ts
pnpm testTsc
```

Ожидается: все тесты зелёные, в том числе
- `tunnel.test.ts` — два туннеля на `127.0.0.1` с эмуляцией несимметричного маршрута (ответы
  собеседника приходят с «чужого» адреса): данные доходят в обе стороны, пакеты с чужим токеном
  отброшены, после подтверждения `path` данные идут только по рабочему адресу;
- `upnp.test.ts` — разбор SSDP-ответа и XML описания IGD, сборка SOAP, реакция на коды 718/725;
- `stats.test.ts` — путь `tunnel` распознаётся по адресу удалённого кандидата.

## Живая проверка (Mamoru ↔ друг, один провайдер)

Предусловия: у обоих сборка с фичей; у друга UPnP на роутере включён, ручной проброс 52353 удалён
(чтобы проверить именно автопроброс); у обоих включён `diagLog`.

| # | Действие | Ожидается |
|---|---|---|
| 1 | Mamoru звонит, друг принимает | «подключено» ≤ 10 с, голос в обе стороны, чип «напрямую (туннель)» |
| 2 | Включить демку 1440p60 | видео идёт; в логе `[P2PCall] stats` потери < 1 %, rtt ≤ 20 мс |
| 3 | Лог друга | `[P2PCall] tunnel` с `upnp: "ok"`, порт 40000–40999 |
| 4 | Положить трубку, через минуту — админка роутера друга (UPnP-список) | проброса `P2PCall` нет |
| 5 | 10 звонков подряд | ≥ 9 подключились (SC-001) |
| 6 | Звонок с собеседником у другого провайдера | путь как до фичи, время подключения ±1 с (SC-003) |
| 7 | Друг выключает UPnP, звонок | не соединяется; у друга подсказка «Включите UPnP на роутере», у Mamoru — «У собеседника выключен UPnP» |
| 8 | Закрыть Discord посреди звонка через диспетчер задач | через ≤ 10 мин проброса на роутере нет (срок жизни) |
