# Research: редизайн P2P-звонка

## R1. Как встроить вкладки рядом с родным звонком Discord

**Решение**: расширить существующий патч `CALL_AREA_PATCH`. Сейчас он вставляет нашу область перед `this.renderCall()`. Вместо этого патч заворачивает вызов:

```
$self.renderCallArea(this.props.channel, this.props.height, () => this.renderCall())
```

Наш `CallSlot` сам вызывает `renderCall()` и по результату решает, что показывать:

| Что идёт | Что рисуем |
|---|---|
| только Discord | его область как есть |
| только P2P | нашу область |
| оба звонка | вкладки; на неактивной вкладке её звонок не рендерим |

**Почему**:
- Есть ли звонок Discord, определяется тем же условием, что у самого Discord (`shouldRenderCall`), а не нашей копией логики.
- Свернуть звонок Discord безопасно: голосовое соединение Discord живёт в RTC-сторе, а не в компоненте. Когда пользователь уходит в другой канал, Discord сам размонтирует эту область.

**Запасной вариант (FR-014)**:
- Если патч не применился, ни нашей области, ни вкладок нет. Это так же, как сейчас при поломке патча, и видно в логе Vencord.
- Если упал сам `CallSlot`, `ErrorBoundary` с `fallback` рисует `renderCall()` Discord. Родной звонок не пропадает из-за нашей ошибки.
- `patches.test.ts` проверяет замену на фрагменте бандла, как сейчас.

**Отвергнуто**:
- Прятать область Discord через CSS `display:none`. Её видео продолжает декодироваться, и Discord может мерить размеры нулевого контейнера.
- Свой стор «идёт ли звонок Discord» через `VoiceStateStore`. Это дублирует условие Discord: например, звонок, на который ты не ответил, тоже рисуется областью.

## R2. Вкладки, когда активен «Звонок Discord»

**Решение**: наш блок `.p2p-tabs` кладётся абсолютно поверх области Discord: сверху по центру, `z-index` выше её шапки. Свою шапку не добавляем.

**Почему**: SC-001 — суммарная высота не должна расти. У шапки звонка Discord в ЛС центр пустой: иконки стоят справа.

**Отвергнуто**: отдельная полоса 40px над областью Discord, потому что она добавляет высоту.

## R3. Индикатор вкладки «Звонок Discord»

**Решение**:
- Число участников — `VoiceStateStore.getVoiceStatesForChannel(channelId)`.
- Кто говорит — `SpeakingStore.isSpeaking(userId)` (через `findStoreLazy("SpeakingStore")`) по тем же userId.
- Оба значения читаются через `useStateFromStores`.

Индикатор вкладки «P2P» строится из уже имеющегося `view`: `members` и `speaking`.

## R4. Какая вкладка активна

**Решение**:
- Активна вкладка звонка, который появился позже.
- Время появления фиксируется в модульной переменной `firstSeen[channelId] = { discord, p2p }`, когда `CallSlot` впервые видит звонок.
- Ручной выбор хранится там же (`pick[channelId]`) и сбрасывается, когда один из звонков закончился.

Чистая функция `pickTab(seen, pick)` вынесена в `tabs.ts` и покрыта тестами.

## R5. Цвет плитки

**Решение**, по порядку:
1. `UserProfileStore.getUserProfile(id)?.accentColor` (int → `#rrggbb`), если профиль уже загружен.
2. Иначе — доминантный цвет аватарки. Аватарку уменьшаем до 16×16 на canvas и берём средний цвет непрозрачных пикселей, кэш по URL аватарки. CDN Discord отдаёт `Access-Control-Allow-Origin: *`, а `img.crossOrigin = "anonymous"` не грязнит canvas. Именно так выглядит скриншот-эталон: красная плитка у красной аватарки.
3. Иначе — `--background-secondary`.

Цвет передаётся в `--p2p-banner`. Вычисление асинхронное, до результата у плитки нейтральный фон.

**Отвергнуто**: запрашивать профиль ради `accentColor`. Это лишний запрос к API Discord на каждого участника.

## R6. Меню устройств и «Добавить в звонок»

**Решение**: родные меню Discord — `ContextMenuApi.openContextMenu(e, () => <Menu.Menu>…)` с `Menu.MenuRadioItem` / `MenuCheckboxItem`. Выглядит как в Discord и не требует своей вёрстки.

- **Шеврон микрофона**: группы «Устройство ввода» и «Устройство вывода» плюс чекбокс «Выключить звук».
- **Шеврон камеры**: группа «Камера».
- **«Добавить в звонок»**: до 10 последних ЛС 1-на-1 (`ChannelStore.getSortedPrivateChannels()` или аналог из `PrivateChannelSortStore`), кроме тех, кто уже в звонке, и тех, кому запрещено добавление (`addBlocked`). Клик вызывает `c.dial(channelId, recipientId)` — тот же путь, что у кнопки в шапке.

Сейчас контроллер не умеет менять устройство посреди звонка. Нужен `setDevice(kind, id)`:
- **ввод** — новый `getMic` → `setTrackAll("mic")`;
- **камера** — переснять, если камера включена;
- **вывод** — `setSinkId` у всех `<audio>`.

Настройка сохраняется в `settings.store`.

## R7. Тултипы

**Решение**: тултипы делаем компонентом `Tooltip` Discord, как сейчас, а не CSS `data-p2p-tip` из дизайн-системы. Так тултипы выглядят как родные, не обрезаются `overflow:hidden` области и сами выбирают сторону. Блок `[data-p2p-tip]` из CSS дизайн-системы не переносим.

## R8. «На весь экран»

**Решение** (уточнено после ревью): в полноэкранный режим уходит всё окно (`document.documentElement.requestFullscreen()`), а сама область получает класс `.p2p-area-full` (`position: fixed; inset: 0; z-index: 1000`).

Почему так: меню устройств и тултипы Discord рисуются в своих слоях вне `.p2p-area`. Если сделать полноэкранной только область, их не будет видно.

Выход — по той же кнопке или по Esc/F11: `fullscreenchange` без `fullscreenElement` снимает класс.

## R9. Иконки

**Решение**:
- `ui/icons.tsx` сохраняет хелпер `svg()`. Пути заменяются строками `d` из README дизайн-системы — 21 иконка, из них нужны 17: `pip`, `popout`, `noise` и `more` не используются (Assumptions спеки).
- Старые имена экспортов сохраняем там, где они используются: `MicIcon`, `MicOffIcon` и т. д. Добавляем `ChevronDownIcon`, `AddUserIcon`, `GridIcon`, `FocusIcon`, `FullscreenIcon`, `SignalIcon`, `PhoneIcon`.
- `PhoneLinkIcon` становится иконкой `p2p-call`.
- `icons.test.ts` проверяет, что каждый путь — непустая строка без `NaN`.

## R10. CSS

**Решение**:
- `styles.css` переписывается на основе `bundle.css` дизайн-системы, с правками:
  - нет `[data-p2p-tip]` (R7);
  - `.p2p-area` не задаёт `height`, высота — инлайн, как сейчас;
  - добавлены `.p2p-tabs-float` (R2) и `:fullscreen` (R8).
- Удаляются старые классы, которых нет в новой разметке: `p2p-plaque*`, `p2p-tiles*`, `p2p-chip` и прочие. Для этого используем grep по `ui/`.
- Классы `IncomingCallModal`, `Contacts`, `SourcePicker` и `QualityControls` сохраняются, если компоненты не переделываются.
