# Quickstart: проверка групповых звонков

## Автотесты

```bash
npx tsx --test src/userplugins/p2pCall/*.test.ts
pnpm testTsc
```

- `group.test.ts`: `mergeRoster` — идемпотентность, коммутативность; одновременные добавления двух людей;
  уход и повторное вступление; предел 5; «остался один» → конец; правило «кто начинает связь» (R5).
- `state.test.ts`: во время звонка `ring` без `auto` больше не даёт `decline busy`, а создаёт приглашение;
  `auto` чужой группы и шестой участник — `busy`.
- `contacts.test.ts`: устройство по представлению — `trusted` для нового контакта, `pending` при другом
  ключе известного, свой ключ пропускается, CPace-ключ не перезаписывается.
- `signaling.test.ts`: новые типы шифруются ключом связи; старый клиент (без `caps`) звонком вдвоём не
  ломается.
- `net` (существующие тесты туннеля): два туннеля по разным `linkId` одновременно, закрытие одного не
  трогает другой.

## Ручная проверка (три ПК: A, B, C; все на релизе с фичей)

| # | Действие | Ожидается |
|---|---|---|
| 1 | A ↔ B в звонке, C звонит A | окно с тремя кнопками ≤ 2 с, у C идёт вызов |
| 2 | «Отклонить» / Esc | у C «отклонено», звонок с B идёт |
| 3 | Повторить, «Положить текущий и принять» | у B звонок завершён, A ↔ C |
| 4 | Повторить, «Добавить сюда» | ≤ 10 с все трое слышат друг друга, у всех по три плитки |
| 5 | A в звонке с B звонит C из ЛС | у C «групповой звонок: A, B», после принятия — как п. 4 |
| 6 | Звонок виден в ЛС | у каждого — в ЛС с каждым участником, с кем ЛС есть |
| 7 | B сбрасывает | A и C говорят дальше, «B вышел» |
| 8 | B закрывает Discord | пропадает у остальных ≤ 15 с |
| 9 | A включает демку втроём | видят оба; голос без прерываний; в логе битрейт демки на связь ≈ половина |
| 10 | Звонок вдвоём с участником на старой версии | как раньше; добавить его в групповой — сообщение «старая версия» |

Логи: `[P2PCall] group` (состав при каждом изменении), `[P2PCall] link` (состояние каждой связи),
`[P2PCall] tunnel` с `linkId`.
