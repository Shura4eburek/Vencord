# Feature Specification: Обновления P2PCall без лишних перезапусков Discord

**Feature Branch**: `feat/p2p-call`

**Created**: 2026-10-18

**Status**: Draft

**Input**: User description: "Автообновление и кнопка «Проверить обновление» должны показывать, что нужно сделать после установки обновления — ничего, перезагрузить окно или перезапустить Discord. Большинство обновлений не должны требовать полного перезапуска: сетевую часть плагина (туннель, UPnP) сделать перезагружаемой без рестарта Discord. Во время P2P-звонка ничего не перезагружать."

## Контекст

Сейчас любое обновление P2PCall заканчивается одинаково — «перезапусти Discord», хотя многие правки
(интерфейс, логика звонка) применились бы простой перезагрузкой окна, а часть могла бы применяться
вообще без действий. За один вечер 17–18.10 вышло пять релизов, и каждый раз оба собеседника
перезапускали Discord полностью.

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Обновление говорит, что нужно сделать (Priority: P1)

Пользователь получает обновление (само или по кнопке «Проверить обновление») и видит одно из трёх:
«обновлено, ничего делать не нужно», «перезагрузи окно» (кнопкой в уведомлении) или «перезапусти
Discord» (кнопкой в уведомлении). Требование всегда соответствует тому, что реально поменялось.

**Why this priority**: это и есть просьба — не перезапускать Discord, когда это не нужно, и не гадать.

**Independent Test**: выпустить три релиза — только с правкой интерфейса, только с правкой сетевой части,
с правкой части, загружаемой при старте Discord — и на установленной копии увидеть соответственно
«перезагрузи окно», «ничего не нужно», «перезапусти Discord»; после указанного действия новая версия работает.

**Acceptance Scenarios**:

1. **Given** релиз меняет только интерфейс или логику звонка, **When** обновление установилось, **Then**
   уведомление предлагает перезагрузить окно, и после перезагрузки окна работает новая версия.
2. **Given** релиз меняет только сетевую часть (туннель, автопроброс), **When** обновление установилось
   вне звонка, **Then** пользователь видит «обновлено, ничего делать не нужно», и следующий звонок
   использует новую сетевую часть.
3. **Given** релиз меняет часть, которая загружается только при старте Discord, **When** обновление
   установилось, **Then** уведомление предлагает перезапустить Discord, как сейчас.
4. **Given** релиз меняет несколько частей, **When** обновление установилось, **Then** показывается самое
   сильное из нужных действий (перезапуск > перезагрузка окна > ничего).
5. **Given** версия уже последняя, **When** нажата «Проверить обновление», **Then** ответ «уже последняя
   версия», без предложений что-то перезапускать.

---

### User Story 2 - Обновление не рвёт звонок (Priority: P1)

Обновление пришло, пока идёт P2P-звонок. Звонок продолжается без помех; применить обновление
предлагается после того, как звонок закончился.

**Why this priority**: оборвать звонок ради обновления хуже, чем не обновиться.

**Independent Test**: во время звонка опубликовать релиз и нажать «Проверить обновление» — звонок не
прерывается; после сброса появляется уведомление с нужным действием.

**Acceptance Scenarios**:

1. **Given** идёт P2P-звонок, **When** установилось обновление любого вида, **Then** ничего не
   перезагружается и сетевая часть звонка не меняется до конца звонка.
2. **Given** обновление отложено из-за звонка, **When** звонок закончился, **Then** пользователь видит
   уведомление с нужным действием (или сетевая часть обновляется сама, если больше ничего не нужно).

---

### User Story 3 - Большинство обновлений без полного перезапуска (Priority: P2)

Правки сетевой части (туннель, автопроброс), которые сейчас требуют перезапуска Discord, применяются
без него.

**Why this priority**: даёт основную экономию, но работает только поверх US1.

**Independent Test**: релиз с правкой только в сетевой части применяется на установленной копии без
перезапуска Discord и без перезагрузки окна; следующий звонок использует новую версию (видно в логе).

**Acceptance Scenarios**:

1. **Given** обновление поменяло только сетевую часть, **When** звонка нет, **Then** новая сетевая часть
   начинает работать сразу, без действий пользователя.
2. **Given** новая сетевая часть не загрузилась (битый файл, ошибка), **When** это обнаружено, **Then**
   продолжает работать прежняя версия, а пользователь видит предложение перезапустить Discord.

---

### Edge Cases

- Сборка с рабочего репозитория (как у Mamoru): автообновление выключено, как сейчас; локальная
  пересборка сетевой части тоже подхватывается без перезапуска Discord.
- Релиз без изменений кода (только версия или описание): «ничего делать не нужно».
- Установленная копия старой версии без нового механизма обновляется на новую: показывается
  «перезапусти Discord» (первый переход всегда требует перезапуска).
- Пользователь игнорирует «перезагрузи окно»: старая версия продолжает работать до перезагрузки, новых
  ошибок нет; при следующем запуске Discord работает новая.
- Подряд вышли два релиза, первый требовал перезапуска, второй — только перезагрузки: показывается
  перезапуск, пока он не выполнен.
- Обновление пришло во время входящего звонка (ещё не принят): считается звонком, ничего не
  перезагружается.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Каждое установленное обновление MUST сопровождаться одним из трёх итогов: «ничего не
  нужно», «перезагрузить окно», «перезапустить Discord».
- **FR-002**: Итог MUST определяться по тому, какие части плагина реально изменились между
  установленной и новой версией, а не по факту новой сборки (служебные метки сборки не считаются
  изменением).
- **FR-003**: Если изменилось несколько частей, итогом MUST быть самое сильное действие.
- **FR-004**: Уведомления «перезагрузить окно» и «перезапустить Discord» MUST содержать кнопку,
  выполняющую это действие; перезапуск MUST сохранять вход в аккаунт (как сейчас).
- **FR-005**: Кнопка «Проверить обновление» MUST показывать тот же итог текстом.
- **FR-006**: Во время P2P-звонка (исходящий, входящий, соединение, разговор) обновление MUST NOT ничего
  перезагружать и MUST NOT подменять работающую сетевую часть.
- **FR-007**: Отложенное из-за звонка действие MUST быть предложено (или выполнено, если это «ничего не
  нужно») после окончания звонка.
- **FR-008**: Сетевая часть плагина (туннель, автопроброс) MUST обновляться без перезапуска Discord и без
  перезагрузки окна.
- **FR-009**: При ошибке загрузки новой сетевой части MUST продолжать работать прежняя, а итогом MUST
  стать «перезапустить Discord».
- **FR-010**: Невыполненное требование перезапуска MUST сохраняться до перезапуска: следующее более
  слабое обновление его не отменяет.
- **FR-011**: Подпись и проверка целостности релизов MUST оставаться не слабее текущих: ни один новый
  файл не применяется без проверки по подписанному манифесту.
- **FR-012**: Публикация релиза MUST сама определять, какие части изменились, без ручной пометки.

### Key Entities

- **Часть плагина**: набор файлов сборки с одинаковым способом применения — «при старте Discord»,
  «перезагрузка окна», «на лету» (сетевая часть).
- **Итог обновления**: ничего / перезагрузить окно / перезапустить Discord; вычисляется из изменившихся
  частей; хранится, пока не выполнен.
- **Манифест релиза**: подписанный список файлов с контрольными суммами и признаком, к какой части
  относится каждый и изменился ли он по существу.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Релиз, меняющий только интерфейс или логику звонка, применяется за ≤ 5 с (перезагрузка
  окна) вместо полного перезапуска Discord.
- **SC-002**: Релиз, меняющий только сетевую часть, применяется без единого действия пользователя.
- **SC-003**: В 100 % случаев показанное действие достаточно: после него работает новая версия (проверка
  по версии в логе/настройках).
- **SC-004**: Ни один P2P-звонок не прерывается из-за обновления.
- **SC-005**: Из пяти релизов 17–18.10 при новом механизме не менее трёх применились бы без полного
  перезапуска (оценка по их фактическим изменениям).

## Assumptions

- Перезагрузка окна Discord сохраняет вход в аккаунт и занимает несколько секунд.
- Часть, загружаемая при старте Discord (обвязка плагина в main-процессе, CSP релеев, само
  автообновление), меняется редко; после выноса сетевой части это в основном правки самой обвязки.
- Пользователи обновляются из подписанных релизов форка; механизм подписи и формат версий сохраняются.
- Первый переход на версию с новым механизмом требует полного перезапуска — это приемлемо.
- Автообновление остаётся выключенным для рабочей сборки из репозитория.
