# Research: обновления без лишних перезапусков

## R1. Как отличить «реально изменилось» от новой сборки

- **Decision**: релиз собирается самим `release.ts` с фиксированными `SOURCE_DATE_EPOCH=1700000000` и
  `VENCORD_HASH=p2pcall`. Тогда сборка детерминирована, и файл, исходники которого не менялись,
  совпадает байт в байт.
- **Проверено (2026-10-18)**: две сборки подряд с этими переменными дали одинаковые sha256 у
  `patcher.js`, `preload.js`, `renderer.js`, `renderer.css`; обычная `pnpm build` — другой `patcher.js`.
- **Изменилось** = sha256 файла на диске у пользователя ≠ sha256 в подписанном манифесте. Хранить
  «установленный манифест» не нужно: правда — файлы на диске (после первого перехода они тоже из
  детерминированной сборки).
- **Цена**: в настройках Vencord хэш сборки будет `p2pcall` вместо коммита — для форка приемлемо.
- **Alternatives**: нормализация (вырезать метки из файлов перед хэшем) — хрупко; ручная пометка в
  релизе — противоречит FR-012.

## R2. Части плагина и их действия

| Файл | Часть | Действие |
|---|---|---|
| `patcher.js` (main: Vencord + `native.ts`, автообновление, CSP) | при старте | перезапуск Discord |
| `preload.js` | при старте | перезапуск Discord (Electron может держать preload в процессе — не рискуем) |
| `renderer.js`, `renderer.css` | окно | перезагрузка окна: `ipcMain.ts:179` читает `renderer.js` с диска при каждой загрузке |
| `p2pcall-net.js` (новый: туннель, UPnP) | на лету | ничего |

Итог = максимум по изменившимся файлам (FR-003). Ни один не изменился — «уже последняя/ничего».

## R3. Сетевая часть «на лету»

- **Decision**: `tunnel.ts`, `upnp.ts`, `tunnelWire.ts` + оркестрация туннеля (сейчас в `native.ts`)
  собираются отдельным бандлом `dist/p2pcall-net.js` (CommonJS, Node, без Electron). `native.ts`
  оставляет тонкие обёртки `tunnel*` и загружает модуль через `require` с очисткой `require.cache`.
- **Когда перезагружается**: при `tunnelPrepare`, если `mtime`/размер файла изменились и активного
  туннеля нет (прошлый звонок уже закрыт тем же вызовом). Звонок не может застать подмену (FR-006).
  То же работает для локальной пересборки у Mamoru (edge case).
- **Ошибка загрузки** (FR-009): остаётся прежний модуль; флаг `netBroken` → итог проверки обновления
  «перезапустить Discord». Если прежнего нет — туннель недоступен, звонки идут как до туннеля.
- **Electron**: модулю нужен только путь `userData` (файл зависшего проброса) — передаётся при создании.
- **Alternatives**: `vm`/`import()` с query-строкой — то же, но сложнее; worker_threads — лишний IPC на
  каждый пакет.

## R4. Совместимость со старыми установками

- Старый `parseManifest` требует ровно 4 файла — манифест с 5 файлами он отклонит, и старые копии
  перестанут обновляться.
- **Decision**: релиз публикует оба манифеста: прежний `manifest.json`/`.sig` (4 файла — старые копии
  обновляются как раньше и получают новое автообновление) и `manifest-v2.json`/`.sig` (5 файлов + схема
  частей) для нового автообновления.
- После первого перехода `p2pcall-net.js` ещё нет: новое автообновление при старте видит отсутствие файла
  и проверяет обновление сразу (не через 10 с), докачивает модуль — итог «ничего не нужно».

## R5. Звонок и отложенное действие

- **Decision**: решение о показе — в рендерере. Если `CallController` не в `idle`/`ended`, итог
  кладётся в «отложенные»; при переходе звонка в `idle`/`ended` показывается уведомление (FR-007).
  Сетевая часть и так подменяется только между звонками (R3).
- **Сохранение требования перезапуска (FR-010)**: в памяти main-процесса — он живёт ровно до
  перезапуска, значит флаг сам сбрасывается тем действием, которое требует. Требование перезагрузки окна
  сбрасывается на `did-navigate` окна, которое его получило.
- **Перезагрузка окна**: `location.reload()` в рендерере (как Ctrl+R; вход сохраняется).

## R6. Сборка сетевого модуля

- **Decision**: дополнительная запись в `scripts/build/build.mjs`, только если существует
  `src/userplugins/p2pCall/net.ts`: `platform: node`, `format: cjs`, `external: ["electron"]`,
  выход `dist/p2pcall-net.js`. Так обычная `pnpm build` и `release.ts` дают один и тот же модуль.
